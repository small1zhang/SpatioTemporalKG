## P0 修改计划：场景生成车辆/行人不合理问题修复

### 一、问题原因清单（按严重度排序）

#### P0-1: 行人 spawn 在车辆道路上（严重，必导致 spawn 失败/穿模）
- **位置**:
  - `scripts/pipeline/smoke_test.py:131-145` 的 `spawn_scenario_traffic` walker 分支
- **现象**: 行人位置 = `spawn_points[idx].location + uniform(-5,5)`，沿用的是**车辆 spawn_points**，再随机扰动 5m，落点几乎一定落在车道上而非人行道/交叉口
- **后果**: spawn 成功率低；即使 spawn 成功，行人立刻被 AI 控制者拽到道路中央，与车流冲突；`is_on_crosswalk`/`is_on_sidewalk` 字段长期为 False（已验证：`phase5_graph.json:4662+` 全部都是 `is_on_crosswalk: false`）
- **对照**: `collect.py:194-226` 和 `run_phases_1_5.py:348-378` **正确**使用了 `world.get_random_location_from_navigation()`（CARLA 提供的导航点，本身就落在人行道/路网可达的步行点位上）

#### P0-2: batch_collect / smoke_test 把 walker 数量参数读成 `pedestrian_count`，但 run_phases_1_5 用 `--walkers`
- **位置**: `scripts/pipeline/batch_collect.py:134`、`smoke_test.py:209`
- **现象**: 两处使用 `yaml_params.get("pedestrian_count", profile["walkers"])`，把读到的值通过 `--walkers` 喂给 `run_phases_1_5.py`
- **YAML 缺失**: 5 个 map_configs/*.yaml 中只有 S00/S02/S21 定义了 `vehicle_count` 或 `pedestrian_count`，其余 11 个场景的 `scenario_parameters` **完全没有** `vehicle_count` / `pedestrian_count` 字段
- **后果**: 各场景 spawn 的车辆数恒等于 `SCENARIO_PROFILES[scenario_id]["vehicles"]`，**忽略了 S13 follow_distance 等"应多车跟车"的语义**；S33 pedestrian_group_size=3 等环境异常也没人/车去匹配
- **影响**: "正常 S00-S02 / 异常 S10-S33"在 spawn 阶段几乎是同一资源配置，未对应场景语义

#### P0-3: ego-centric 椭圆方向依赖 ego spawn_point 朝向而非 ego 实际朝向
- **位置**: `collect.py:229-251`（`_ellipse_distance_to_ego`）+ `run_phases_1_5.py:293-301`
- **现象**: 椭圆中心是 `ego_spawn_point.location`，朝向是 `ego_spawn_point.rotation.yaw`。但 autopilot 启动后 ego 会迅速偏离 spawn 朝向；同时 `ego_spawn_pt.rotation.yaw` 是地图预设的，很多 spawn point yaw 与实际道路方向不一致
- **后果**: ego 前方半径 70m 的"椭圆"经常斜着覆盖反向车道或路边；`radius_front=70 / radius_rear=30` 失去意义；填充的 NPC 起位置与 ego 实际运动方向不匹配，"前车急刹 sudd_brk"的 spawn 上下文错位
- **次生**: 长跑 20min 全程，`bind_targets` 用的 ego_tf 是实时位姿，但 spawn 时用的是 spawn_point 位姿，**两者朝向不一致**——前车筛选按 spawn_point 的 yaw 把"侧方"车放到实际"前方"，导致 `sudd_brk` 拿到的不是真正前车

#### P0-4: SCENARIO_PROFILES 与 map_configs/*.yaml / scenario_library.py 数量不一致
- **位置**: `batch_collect.py:63-78`、`smoke_test.py:36-51`
- **现象**: 三个独立"场景→车/人数量"映射表（scenario_library.py 的 `make_Sxx_*` 注释里写的车数、batch_collect 的 `SCENARIO_PROFILES`、smoke_test 的 `SCENARIO_TRAFFIC_PROFILES`），彼此轻微不同（如 S22 在 batch 是 6v/2w，但 scenario_library.py 实例化 1 辆 emergency + 其他 ≠ 6 辆）
- **后果**: 三处配置漂移，"场景语义"和"采集时的实际流量"无法对齐

#### P0-5: 异常注入缺乏行人目标（ped_crs / obs_blk 流于形式）
- **位置**: `anomaly_scheduler.py:266-267` 的 `else` 分支明确 `# ped_crs / obs_blk 在 collect.py 的 spawn 阶段已处理 target / log += " [skip]"`
- **现象**: 翻 `collect.py` 全文，**没有任何专门给 `ped_crs` spawn 行人朝 ego 走、给 `obs_blk` spawn 障碍物的代码**——只有 `bind_targets` 给车辆事件配 actor，没有 walker target 绑定、没有 obstacle spawn
- **后果**: 调度表里 9 类异常，3 类（ped_crs/obs_blk/部分 sudd_*）触发时实际"啥也不发生"，只是写了一行 `[skip]` 日志，数据集里这些样本被标了 `is_anomaly=1` 但帧本身无异常特征，造成标签噪声

#### P0-6: get_random_location_from_navigation 10 次重试可能不足（大地图稀疏导航点）
- **位置**: `collect.py:206-210`、`run_phases_1_5.py:358-362`：`for _try in range(10)`；`collect.py:330` ego-centric 模式 `for _try in range(50)` 已经更宽容
- **现象**: Town04/Town05 等大地图行人可达点稀疏，10 次重试常常拿不到 `loc`，`if loc is None: continue` 静默跳过，最终 `spawned_walkers` 数量 << `args.walkers`，且无可视化告警
- **后果**: 默认模式 walker 实际 spawn 数可能比配置少 30-50%，对 S02/S10/S33 等需要 5-8 行人的场景影响尤其大

### 二、修改方案（最小化 diff，集中处 P0 优先）

只动 **P0-1 / P0-2 / P0-6** 三个会直接造成 spawn 失败或语义错误的硬伤，按用户优先级 P0 处理。后续 P1 再处理 P0-4（场景参数对齐）、P0-5（ped_crs/obs_blk 实体注入）、P0-3（椭圆朝向）。

#### 修改 1 — P0-1：smoke_test.py 行人 spawn 改用导航点

**文件**: `scripts/pipeline/smoke_test.py:126-148`

将 `spawn_points[idx].location + uniform(-5, 5)` 改为 `world.get_random_location_from_navigation()`（与 collect.py / run_phases_1_5.py 对齐）。

```python
# 修改前 (L126-147):
if n_walkers > 0:
    walker_bps = bp_lib.filter("walker.pedestrian.*")
    walker_controller_bp = bp_lib.find("controller.ai.walker")
    for i in range(n_walkers):
        for _try in range(10):
            idx = random.randint(0, len(spawn_points) - 1)
            bp = random.choice(walker_bps)
            try:
                loc = carla.Location(
                    spawn_points[idx].location.x + random.uniform(-5, 5),
                    spawn_points[idx].location.y + random.uniform(-5, 5),
                    spawn_points[idx].location.z,
                )
                w = world.spawn_actor(bp, carla.Transform(loc))
                ...

# 修改后:
if n_walkers > 0:
    walker_bps = bp_lib.filter("walker.pedestrian.*")
    walker_controller_bp = bp_lib.find("controller.ai.walker")
    for i in range(n_walkers):
        bp = random.choice(walker_bps)
        loc = None
        for _try in range(20):  # ← 与 collect.py 一致 + 增加重试次数 (P0-6)
            _loc = world.get_random_location_from_navigation()
            if _loc is not None:
                loc = _loc
                break
        if loc is None:
            continue
        try:
            w = world.spawn_actor(bp, carla.Transform(loc))
            ctl = world.spawn_actor(walker_controller_bp, carla.Transform(), attach_to=w)
            ctl.start()
            ctl.go_to_location(world.get_random_location_from_navigation())
            ctl.set_max_speed(1.0 + random.random())
            spawned_walkers.append((w, ctl))
        except RuntimeError:
            continue
```

**收益**: 行人落到人行道/交叉口，`is_on_crosswalk/is_on_sidewalk` 不再恒 False；与另外两条 spawn 路径行为一致。

#### 修改 2 — P0-1 残留：smoke_test.py 不再使用 spawn_points for walker

同上的修改其实已经移除了 `spawn_points` 在 walker 分支的使用，但 `spawn_points = map_.get_spawn_points()` 在 L101 仍然被车辆分支使用，需要保留即可，无需动。

#### 修改 3 — P0-6：collect.py / run_phases_1_5.py 默认模式 walker 重试 10 → 30，并打 warning

**文件**: `scripts/long_run/collect.py:206-211`、`scripts/pipeline/run_phases_1_5.py:357-364`

```python
# collect.py 修改前 (L205-211):
loc = None
for _try in range(10):
    _loc = world.get_random_location_from_navigation()
    if _loc is not None:
        loc = _loc
        break
if loc is None:
    continue

# 修改后:
loc = None

        loc = _loc
        break
if loc is None:
    continue
```

`run_phases_1_5.py:358` 同步把 `for _try in range(10)` 改 `for _try in range(30)`。

**额外**: 在 `spawn_walkers` / `spawn_walkers_ego_centric` 函数返回后，在调用方 print 一行告警当 `len(spawned_walkers) < n` 时（已经在 collect.py:800、run_phases_1_5.py:378 有 print，不需要再加）。

#### 修改 4 — P0-2：补齐 5 个 map_configs/*.yaml 缺失的 vehicle_count / pedestrian_count

**文件**: `map_configs/Town01.yaml` / `Town02.yaml` / `Town04.yaml` / `Town05.yaml` / `Town10HD.yaml` 的 `scenario_parameters`

逐场景补 `vehicle_count` / `pedestrian_count`，对齐 `batch_collect.py:63-78 SCENARIO_PROFILES` 的车辆/行人数量定基线，再按 scenario 语义调整：

- S00 基线直行跟车 → 2-3v/0w（与 scenario_library make_S00_baseline_following "2 车道 + 2 车"对齐）
- S01 信号路口 → 沿用 current vehicle_count 设置即可（已有/补默认）
- S02 行人通行 → 增加 pedestrian_count 明确写
- S10 行人突然横穿 → pedestrian_count: 3-5 (已有 `appearance_distance`)
- S11 无保护左转 → vehicle_count: 6
- S12 红灯闯行 → vehicle_count: 5, pedestrian_count: 2
- S13 跟车过近 → vehicle_count: 8（强调跟车队列）/ 0w
- S20 汇入冲突 → vehicle_count: 10
- S21 三方无信号 → vehicle_count: 8
- S22 紧急车辆 → vehicle_count: 6（1 emergency + 5 普通）, pedestrian_count: 2

#### 修改 5 — P0-2 配套：smoke_test.py / batch_collect.py 的读取一致性

**文件**: `scripts/pipeline/smoke_test.py:206-209`、`scripts/pipeline/batch_collect.py:132-134`

两者优先读 yaml 的 `vehicle_count` / `pedestrian_count`、fallback 走 profile。这部分代码本身没问题，问题在于 yaml 字段缺失。补齐 yaml 后，需要再让 fallback 字段统一命名为 `vehicles` / `walkers`（与 `SCENARIO_PROFILES` 一致），避免 `vehicle_count` vs `vehicles` 的命名分歧——把 `SCENARIO_PROFILES` 改为使用 `vehicle_count` / `pedestrian_count` 与 yaml 对齐。

```python
# batch_collect.py 修改前 (L63-78):
SCENARIO_PROFILES = {
    "S00": {"frames": 100, "vehicles": 3,  "walkers": 0},
    ...
}

# 修改后:
SCENARIO_PROFILES = {
    "S00": {"frames": 100, "vehicle_count": 3,  "pedestrian_count": 0},
    ...
}

# batch_collect.py L132-134 修改前:
frames = yaml_params.get("frames", profile["frames"])
n_vehicles = yaml_params.get("vehicle_count", profile["vehicles"])
n_walkers = yaml_params.get("pedestrian_count", profile["walkers"])

# 修改后 (字段名统一):
frames = yaml_params.get("frames", profile["frames"])
n_vehicles = yaml_params.get("vehicle_count", profile["vehicle_count"])
n_walkers = yaml_params.get("pedestrian_count", profile["pedestrian_count"])
```

`smoke_test.py:36-51 SCENARIO_TRAFFIC_PROFILES` 同步把 `vehicles`/`walkers` 改 `vehicle_count`/`pedestrian_count`，调整 L208-209 的 lookup 与之一致。

**文件**: `scripts/long_run/collect.py` 在 L800 附近 / `scripts/pipeline/run_phases_1_5.py` 在 L378 附近，把 walker spawn 的 print 加上预期 vs 实际差距提示：

# collect.py L800 修改前:

### 四、影响范围 & 风险

- **不破坏现有 smoke_test / batch_collect 输出结构**: `result.json`、`metadata.json` schema 不变
- **yaml 字段补齐后向后兼容**: 现有 `batch_collect.py` `yaml_params.get(..., profile["vehicles"])` 在 profile key 改名后，旧 yaml（没有 vehicle_count）会读 fallback profile，需配套修改 5（三表对齐）一起做才安全
- **行人 spawn 行为变化**: smoke_test.py 行人未来会出现在交叉路口/人行道而非道路中央——这可能改变现有 smoke_test 的某些帧结构（行人在 view 内的概率↑），但由于 smoke_test 主要做冒烟用，不需要保真
- **重试从 10 升到 30**: 单次 walker spawn 最坏多 ~50ms（30 次 RPC），20 张图 × 8 行人 ≤ 1s 额外冷启动时间，可接受
- **不涉及数据消费侧**: `build_anomaly_dataset.py` / `pipeline.py` 等下游只读 phase1_extraction.json，spawn 阶段改不影响
