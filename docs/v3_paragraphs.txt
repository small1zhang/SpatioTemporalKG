  15 | 1.3 基础表达单元：实体、属性、关系
  16 | 1.3.1 核心原则
  17 | 实体、属性、关系是贯穿全图谱的基础建模单元，本身不构成独立的一层，而是每一层内部数据的表达方式。
  18 | 1.3.2 命名规范
  19 | **实体节点 Label**：PascalCase，如 `VehicleEntity`、`SafetyViolation`
  20 | **关系类型**：snake_case，如 `in_lane`、`following`、`supportedByEvidence`
  21 | **属性字段**：snake_case，如 `location_x`、`speed_kmh`
  22 | **谓词命名**：PascalCase，如 `DangerousState(A,B,t)`、`RedLightViolation(A,R,t)`
  23 | 1.3.3 双表达对齐原则（节点+边双轨）
  24 | **节点表达**：每个规则触发实例建模为 `SafetyViolation` 节点（或 `RuleInstance` 节点），携带时间戳、证据链等信息
  25 | **关系表达**：同一事件同时以关系边形式连接涉及实体，如 `VehicleA -[violatesRedLight]-> RoadElementR`
  26 | **对应关系**：每个 `SafetyViolation` 节点有唯一 ID，其 `reason` 字段值与对应关系边的 `type` 一致。形式化谓词（如 `DangerousState(A,B,t)`）作为元数据存储于节点属性中

  41 | 1.5 横向机制：动态更新
  42 | 1.5.1 定位
  43 | 动态更新机制不是场景-行为-规则中的某一层内容，而是让这三层都能随时间增量演化的一套横向机制。 本身不产生新的语义内容，只负责"图谱如何被更新"。
  44 | 1.5.2 四类更新动作
  45 | 1.5.3 机制流程
  46 | 每一帧
  │
  ▼
CARLA 真值提取 → 原始数据
  │
  ▼
构建帧快照 G_t → 实体集合 + 空间关系
  │
  ▼
计算差分 Δg_t → 相对 G_{t-1} 的变化
  │
  ▼
增量更新图谱 → 节点增删 / 属性更新 / 边增删
  │
  ▼
规则推理 (RSS+交规) → 产出规则事件
  │
  ▼
事件反向插入图谱 → SafetyViolation 节点
  47 | 1.5.4 事件驱动反向插入机制
  48 | 规则层判定出的 SafetyViolation（如 `DangerousState(A,B,t)`）作为事件节点动态插入图谱，触发新一轮图谱更新：
  49 | SafetyViolation 节点携带 `frame_id`, `timestamp`, `severity`, `evidence_path` 属性
  50 | 通过 `supportedByEvidence` 边连回场景层/行为层相关实体/关系
  51 | 该事件被 GNN 下游模块消费，作为异常检测的先验特征
  52 | 事件节点在 Neo4j 中可追溯查询，支持异常回放与因果分析
  53 | 这一机制构成了规则驱动（RSS/交规推理）与数据驱动（图谱更新）的实际耦合点，而不只是两者并列存在。

  96 | 采用「帧级属性版本化 + 显式生命周期标记」混合模型：

 104 | 1.11 核心公理
 105 | 1.11.1 基础公理集合
 106 | 1.11.2 推理规则示例
 107 | 安全距离公理（RSS 子层）
 108 | SafeDistanceViolation(A, B, t) ←
    VehicleEntity(A) ∧ VehicleEntity(B) ∧
    is_in_same_lane(A, B, t) ∧
    longitudinal_distance(A, B, t) < d_min(A, B, t)
 109 | 其中：
 110 | d_min(A, B, t) = v_A(t)·ρ + 0.5·a_max,accel·ρ²
               + (v_A(t)+a_max,accel·ρ)² / (2·a_min,brake)
               - v_B(t)² / (2·a_brake)
 111 | 参数集：
 112 | ρ = 反应时间（默认 0.1 秒，可调）
 113 | a_max,accel = 舒适加速度上限
 114 | a_min,brake = 最小合理刹车减速度
 115 | a_brake = 最大刹车减速度
 116 | 横向危险公理（RSS 子层）
 117 | LateralDangerousState(A, B, t) ←
    VehicleEntity(A) ∧ VehicleEntity(B) ∧
    bbox_lateral_distance(A, B, t) < d_lat_min(t)
 118 | 行人让行公理（交规子层）
 119 | YieldingToPedestrianViolation(A, P, t) ←
    VehicleEntity(A) ∧ PedestrianEntity(P) ∧
    is_on_crosswalk(P, t) ∧
    relative_distance(A, P, t) < 15m ∧
    speed(A, t) > 0.5 m/s
 120 | 闯红灯公理（交规子层）
 121 | RedLightViolation(A, R, t) ←
    VehicleEntity(A) ∧ RoadElementEntity(R) ∧
    in_junction(A, R, t) ∧
    signal_color_at(A, t-Δ) = Red ∧
    speed(A, t) > 0.3 m/s

 186 | 2.6 节点设计小结
 187 | **6 类节点**：4 类动态/静态实体 + 1 类环境快照 + 1 类帧根节点
 188 | **30+ 直接可用字段**：来自 CARLA 原生 API
 189 | **10+ 可计算字段**：均为 O(1) 或 O(n) 复杂度
 190 | **属性版本化**：保证时态可追溯性
 191 | **多标签 NEO4J 节点**：Road/Lane/Junction 通过多标签 Neo4j 节点表达
 192 | 2.7 设计原则
 193 | 场景层关系描述"实体之间在同一帧内的空间、拓扑、包含关系"，是行为层与规则层的语义基石。
 194 | **同帧性**：所有场景层关系成立的时态戳为某一特定帧 t
 195 | **几何确定性**：每条关系可由 CARLA 真值直接计算
 196 | **零防抖**：场景层空间关系不等抖（区别于行为关系需防抖）
 197 | **唯一性**：每对 (src, dst, type, t) 唯一

 201 | 2.9 详细关系定义
 202 | 2.9.1 拓扑关系
 203 | in_lane
 204 | VehicleEntity -[in_lane]-> RoadElementEntity
 205 | on_road
 206 | 条件：vehicle 中心在 road 多边形内（不区分车道）
 207 | 复杂度：O(k)，k=路段数
 208 | 用途：辅助异常检测（如车辆离开道路）
 209 | in_junction
 210 | 条件：waypoint(v).junction_id == road.junction_id 且 junction_id != -1
 211 | 复杂度：O(1)
 212 | 用途：路口场景识别，配合交通灯状态判断违规
 213 | adjacent_lane
 214 | 条件：lane_a.get_left_lane() == lane_b 或 get_right_lane() == lane_b
 215 | 复杂度：O(1)
 216 | 用途：变道行为识别基础
 217 | lane_connects
 218 | 条件：lane_a.next(distance) 包含 lane_b
 219 | 复杂度：O(n)
 220 | 用途：道路网络拓扑建立

 274 | 3.1 设计原则
 275 | 行为层是场景层在时间维度上的语义提炼，回答"这些实体在做什么、怎么互动"。
 276 | 3.1.1 核心设计决策：节点 + 边双轨
 277 | 经过权衡，本研究采用节点 + 边双轨表达方案：
 278 | 两者通过 `manifestsAs` 边关联：
 279 | ManeuverNode -[manifestsAs]-> {following_edge | approaching_edge | ...}
 280 | 节点的核心价值：
 281 | 行为有明确的起止时间（`frame_start`, `frame_end`），节点可携带完整生命周期
 282 | 行为可挂载派生属性（持续帧数、强度、速度变化等），节点表现力更强
 283 | 复杂行为（如超车）由多个原子行为组合而成，节点可链接子行为形成行为序列
 284 | 边的核心价值：
 285 | 直接表达实体间关系，图查询自然
 286 | GNN 模型消费边表更直接
 287 | 关系是行为的"瞬时语义快照"，节点是行为的"持续语义实例"

 331 | 3.4.1 防抖机制
 332 | 行为关系（特别是 following、approaching、yielding_to）在帧间可能因浮点精度、CARLA 物理引擎抖动而产生闪烁，引入「持续帧数阈值」机制：
 333 | 3.4.2 阈值表
 334 | 3.4.3 防抖实现伪代码
 335 | class RelationDebouncer:
    def __init__(self, threshold):
        self.counter = {}
        self.active = {}
        self.threshold = threshold
    
    def update(self, key, condition_met, frame_id):
        if condition_met:
            self.counter[key] = self.counter.get(key, 0) + 1
            if self.counter[key] >= self.threshold:
                if key not in self.active:
                    self._create_edge(key, frame_id)
                    self.active[key] = frame_id
        else:
            if key in self.active:
                self.counter[key] = 0
                if frame_id - self.active[key] >= self.threshold:
                    self._delete_edge(key, frame_id)
                    del self.active[key]
            else:
                self.counter[key] = 0

 406 | 4.8 RSS 形式化模型
 407 | 4.8.1 纵向安全距离
 408 | 给定前车 B、后车 A，二者在同一车道且 ahead_of(B,A)，则纵向最小安全距离定义为：
 409 | $$
 410 | d_{\min}^{\text{long}}(A, B, t) = \max\left(0,\; v_A(t)\cdot\rho + \frac{1}{2} a_{\max,\text{accel}}\cdot \rho^2 + \frac{(v_A(t) + a_{\max,\text{accel}}\cdot\rho)^2}{2\, a_{\min,\text{brake}}} - \frac{v_B(t)^2}{2\, a_{\text{brake}}}\right)
 411 | $$
 412 | 参数集合：
 413 | 纵向危险判定：
 414 | $$
 415 | \text{SafeDistanceViolation}(A, B, t) \iff d^{\text{long}}(A, B, t) < d_{\min}^{\text{long}}(A, B, t)
 416 | $$
 417 | 4.8.2 横向安全距离
 418 | $$
 419 | d_{\min}^{\text{lat}}(A, B, t) = \mu + \frac{v_{\text{lat}, A}(t)^2}{2\, a_{\min,\text{lat,brake}}} + \rho\cdot v_{\text{lat}, A}(t) - \frac{v_{\text{lat}, B}(t)^2}{2\, a_{\min,\text{lat,brake}, B}}
 420 | $$
 421 | 横向危险判定：
 422 | $$
 423 | \text{LateralDangerousState}(A, B, t) \iff d^{\text{lat}}(A, B, t) < d_{\min}^{\text{lat}}(A, B, t)
 424 | $$
 425 | 参数：
 426 | 4.8.3 复合状态与责任
 427 | $$
 428 | \text{DangerousState}(A, B, t) = \text{SafeDistanceViolation}(A, B, t) \lor \text{LateralDangerousState}(A, B, t)
 429 | $$
 430 | 反应不当公理：若 DangerousState(A,B,t) 在连续 3 帧内 ego.brake < 0.3 则触发：
 431 | $$
 432 | \text{NoProperResponse}(A, t) = \text{DangerousState}(A, B, t) \land \bigwedge_{k=0}^{2} \text{brake}(A, t+k) < 0.3
 433 | $$
 434 | 责任归因：
 435 | $$
 436 | \text{ResponsibleAgent}(A, \text{event}_k) \iff \text{NoProperResponse}(A, t) \land \text{B}(t) \text{ 行为合规}
 437 | $$

 573 | 5.5 增量更新算法
 574 | 5.5.1 单帧增量更新主流程
 575 | def incremental_update(frame_id, G_prev, Δg_t, neo4j_conn):
    """
    输入: 前帧图谱 G_prev, 帧差分 Δg_t, Neo4j 连接
    输出: 更新后的 G_curr
    """
    # 1. 实体更新
    for actor in Δg_t.delta_entities.added:
        create_entity_node(actor, frame_id, neo4j_conn)
    for actor in Δg_t.delta_entities.removed:
        deactivate_entity(actor, frame_id, neo4j_conn)

    # 2. 属性更新
    for entity_id, changes in Δg_t.delta_attrs.items():
        for attr, (old_val, new_val) in changes.items():
            update_attribute(entity_id, attr, new_val, frame_id, neo4j_conn)

    # 3. 关系更新
    for rel in Δg_t.delta_relations.added:
        create_relation(rel, frame_id, neo4j_conn)
    for rel in Δg_t.delta_relations.removed:
        deactivate_relation(rel, frame_id, neo4j_conn)
    for rel in Δg_t.delta_relations.updated:
        update_relation(rel, frame_id, neo4j_conn)

    # 4. 规则推理
    rule_results = run_rule_engine(G_prev, Δg_t)

    # 5. 规则事件反向插入
    for violation in rule_results.new_violations:
        create_safety_violation_node(violation, neo4j_conn)
        create_violates_edge(violation, neo4j_conn)
        create_evidence_chain(violation, neo4j_conn)

    return G_curr

 635 | def export_for_gnn(neo4j_conn, frame_start, frame_end, road_id):
    cypher = """
    MATCH (center:RoadElementEntity {road_id: $road_id})
    MATCH (center)<-[r:in_lane]-(v:Vehicle)
    WHERE r.frame_id >= $frame_start AND r.frame_id <= $frame_end
    OPTIONAL MATCH (v)-[b:following]->(w:Vehicle)
      WHERE b.frame_id >= $frame_start AND b.frame_id <= $frame_end
    OPTIONAL MATCH (v)-[sv:violates]->()
      WHERE sv.frame_id >= $frame_start AND sv.frame_id <= $frame_end
    RETURN v, b, w, sv, r, center
    """
    result = neo4j_conn.run(cypher, road_id=road_id, frame_start=frame_start, frame_end=frame_end)
    return to_pyg_format(result)

 673 | class KGConstructionPipeline:
    def __init__(self, carla_world, neo4j_driver):
        self.world = carla_world
        self.neo4j = neo4j_driver
        self.prev_snapshot = None
        self.debouncers = {}  # 行为关系防抖
        self.tl_lane_map = build_traffic_light_lane_map(carla_world.get_map())

    def run_frame(self, frame_id):
        snapshot = self._extract_frame(frame_id)
        delta = self._compute_delta(frame_id, snapshot, self.prev_snapshot)
        self._write_to_neo4j(snapshot, delta)
        violations = self._run_rule_engine(snapshot)
        self._write_violations(violations, neo4j=self.neo4j)
        self.prev_snapshot = snapshot

    def _extract_frame(self, frame_id):
        # 提取所有 actor
        vehicles = [extract_vehicle(v) for v in self.world.get_actors().filter('vehicle.*')]
        peds = [extract_pedestrian(p) for p in self.world.get_actors().filter('walker.*')]
        tls = [extract_traffic_light(t) for t in self.world.get_actors().filter('traffic.*')]
        weather = extract_weather(self.world.get_weather())
        # 计算派生属性
        for v in vehicles:
            compute_derived_attributes(v, self.world.get_map(), self.tl_lane_map)
        # 生成空间关系
        spatial_rels = generate_spatial_relations(vehicles, peds, tls, self.world.get_map())
        # 生成行为关系（带防抖）
        behavior_rels = generate_behavior_relations(
            vehicles, peds, spatial_rels, self.debouncers, frame_id
        )
        return FrameSnapshot(
            frame_id=frame_id,
            vehicles=vehicles, peds=peds, tls=tls,
            weather=weather, spatial_rels=spatial_rels,
            behavior_rels=behavior_rels
        )

    def _run_rule_engine(self, snapshot):
        violations = []
        # RSS 子层
        violations += check_rss_longitudinal(snapshot.vehicles, self.params)
        violations += check_rss_lateral(snapshot.vehicles, self.params)
        violations += check_no_proper_response(snapshot, self.prev_snapshot)
        # 交规子层
        violations += check_red_light(snapshot, self.tl_lane_map)
        violations += check_lane_crossing(snapshot)
        violations += check_yielding_pedestrian(snapshot)
        violations += check_speed_violation(snapshot, snapshot.weather)
        violations += check_illegal_u_turn(snapshot)
        violations += check_junction_yield(snapshot)
        return violations

 675 | def write_vehicle_to_neo4j(neo4j_driver, vehicle, frame_id):
    query = """
    MERGE (v:Vehicle {vehicle_id: $vehicle_id})
    ON CREATE SET v.frame_start = $frame_id, v.is_active = true
    SET v.vehicle_type = $vehicle_type,
        v.location_x = $location_x, v.location_y = $location_y, v.location_z = $location_z,
        v.velocity_x = $velocity_x, v.velocity_y = $velocity_y, v.velocity_z = $velocity_z,
        v.speed = $speed, v.speed_kmh = $speed_kmh,

        v.throttle = $throttle, v.brake = $brake, v.steer = $steer,
        v.bbox_extent_x = $bbox_extent_x, v.bbox_extent_y = $bbox_extent_y,
        v.is_ego = $is_ego,

def write_relation_to_neo4j(neo4j_driver, src_id, dst_id, rel_type, attrs, frame_id):
    query = f"""
    MATCH (src {{vehicle_id: $src_id}})
    MATCH (dst {{vehicle_id: $dst_id}})
    MERGE (src)-[r:{rel_type}]->(dst)
    SET r.frame_id = $frame_id,
        r.valid = true,
        r.last_update_frame = $frame_id,
        r += $attrs
    RETURN r
    """
    neo4j_driver.run(query, src_id=src_id, dst_id=dst_id, attrs=attrs, frame_id=frame_id)
